GOOGLE_CLIENT_ID       OAuth2 Google                       = coloque_seu_client_id_aqui.apps.googleusercontent.com  (*)
GOOGLE_CLIENT_SECRET   OAuth2 Google                       = coloque_seu_client_secret_aqui                         (*)
OAUTH2_ISSUER_URI      ex: https://accounts.google.com     = https://accounts.google.com

(*) VALOR EH PLACEHOLDER NO CONTAINER (nunca foram credenciais reais).

    GOOGLE_CLIENT_ID/SECRET sao textos de exemplo.

--------------------------------------------------------------------------------
VALORES REAIS ENCONTRADOS
--------------------------------------------------------------------------------

DB_USER     = usuario
DB_PASSWORD = senha
DB_NAME     = meubanco

NOTA:
- No docker-compose, o Postgres recebe POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB
  e a aplicacao recebe DB_URL/DB_NAME/DB_USER/DB_PASSWORD (passados direto do .env).
- Datasource montado em application.yml: jdbc:postgresql://${DB_URL}/${DB_NAME}
- Fixos em application.yml (nao sao env vars):
    MAIL_HOST=smtp.hostinger.com   MAIL_PORT=465
    MAIL_FROM=no-reply@lucasfncode.com.br
    INSIGHT_URL=http://insights_app:8000
    JWT_EXPIRATION=86400000
- Opcionais (default em application.yml, podem ser sobrescritos por env):
    JWT_ISSUER=http://backend-leads.local     (iss claim dos tokens locais; usado no decoder/routing)
    FRONTEND_URL=http://localhost:3000        (redirect apos login Google)

RODAR VIA DOCKER COMPOSE
--------------------------------------------------------------------------------

  docker network create lead-network   # uma vez, se nao existir
  docker compose up -d

--------------------------------------------------------------------------------
ACESSAR O POSTGRES
--------------------------------------------------------------------------------

1) Dentro da rede do compose (nome de rede: postgres ou postgres-backend-leads):
     docker exec -it postgres-backend-leads psql -U usuario -d meubanco

2) Do host na porta 5432 (para spring-boot:run local): nao esta publicado.
   Para publicar, rode com um override:
     docker run -d --rm --name backend-leads-db \
       -e POSTGRES_USER=usuario -e POSTGRES_PASSWORD=senha -e POSTGRES_DB=meubanco \
       -p 127.0.0.1:5432:5432 -v pgdata:/var/lib/postgresql/data \
       postgres:16.10
   OU crie /tmp/opencode/compose-override.yml com services.postgres.ports e rode:
     docker compose -f docker-compose.yml -f /tmp/opencode/compose-override.yml up -d postgres

--------------------------------------------------------------------------------
INTEGRACAO COM A REDE EXTERNA (lead-network / insights_app)
--------------------------------------------------------------------------------

O servico app do compose participa de backend-leads_backend-internal E lead-network.
O app fala com o insights via http://insights_app:8000, que deve estar na rede
lead-network. Se a rede nao existir:
     docker network create lead-network
(lead-network ja existe neste ambiente.)
